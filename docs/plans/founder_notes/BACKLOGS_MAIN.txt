2. Flow D in detail

What the closet does today (checked in the code and on a live server just now):
- One big request. CriterionBookCloset.tsx:869 asks for /books?limit=3000&only_discussed=true&exclude_general=true. That returns 2,018 books in 2,151,353 bytes (2.15 MB), uncompressed because the API has no gzip, in 0.51 s locally.
- Rows carry far more than the shelf shows. Every row includes description, rating, members, meetups and Goodreads data. The closet's spines use only id, title, author, covers, discussion count, first-discussed date, year, and the first two meetup numbers (CriterionBookCloset.tsx:2040–2057).
- The modal reuses those heavy rows. CriterionDetailModal.tsx shows the same data, plus one fetchBookSynopsis call.
- The book page fetches again. /books/[id] calls fetchBook separately, so the same book is downloaded twice.
- Every book is drawn at once. The closet has no IntersectionObserver and no other way of drawing only what's on screen.

The saving, re-measured on the closet's real request. The 82.9% in PRD §9.2 came from the unfiltered list, so it was too optimistic:
