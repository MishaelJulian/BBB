# Slice C (admin tools): notes and report (2026-10-19)
Branch `slice-c` (off `ui/slice-a`) in worktree `BBB-vercel-demo-slice-c`. `npx tsc --noEmit` and `next build` pass. 13 unit tests pass against a throwaway Postgres. Nothing pushed, nothing written to the live database, storage, GitHub or Vercel.

## What is done
1. Console home `/admin` (A1): status line, Record a meetup, the folded-corner draft (kept in the phone's localStorage), "This year against last" with an inline SVG area chart (readers per meetup, last 12 meetups that have readers recorded, indexed to the first; fewer than 3 points shows a note, no invented trend), Tools, Do next (all counts from queries: no readers 32, no venue 9, guests who attended twice, no photo), Recent changes (Mine / Everyone) with real Undo. The legacy 2,168-line page is replaced (history only).
2. All changes `/admin/changes` from `audit_log`: filter by type and person, search, 7-day Undo. An undo is a new audited change (`change.undo`). It is offered only when the current state still matches (a later edit blocks it with "Changed again since"). Undoable: hide/show, make a member, rename, remove member (full restore), meetup edit, recorded meetup (moves it to the 7-day trash), meetup delete, group photo change, book edit, book merge, book delete, general-discussion toggle, claim code (revokes it). Marked "Not possible" with the reason: legacy hard-deleted meetups, removed book entries (no copy was saved), member-made changes, restores, enrich runs, undos.
3. Members `/admin/members`, `/admin/members/[id]`: tabs and counts from the database (All 140, Member 114, BYOB 18, Guest 8, Hidden 1, Removed), search, linked filter; edit name, make a member, hide/show, remove (7-day restore; the old remove lost attendance, status and code on restore: new `removeMemberFull`/`restoreMemberFull` keep a copy of them), Make a claim code = personal invite link `https://<site>/join#code=XXXXX-XXXXX` (`&pin=1` with a PIN), link and PIN shown once with Copy, Copy PIN and Share. Reset codes are Slice D: not built.
4. Codes `/admin/codes`: issued invites with member, issued by, issued at, expires, status Active/Used/Expired/Revoked (new `revoked_at`), New code, Revoke.
5. Books `/admin/books`, `/admin/books/[id]`: tabs No author 156 / No cover 278 / No ISBN from the database, search; edit title, author (suggestions), translator (title gets "(tr. Name)" and a `translation_of` relation to the base-title book when one exists, the club's convention), publisher, ISBN (check digit verified), year, cover link, synopsis; Look up details runs on the server (Open Library, then Apple Books), accepts a result only when the title matches, fills only empty fields and shows what each source said; Merge into another book and Delete book (blocked while it has discussions), both with undo data.
6. Meetups `/admin/meetups`, `/admin/meetups/[number]`: tabs All / No readers / No venue / No photo / No PDF / Deleted; group photo upload (jpg/png/webp checked from the bytes, 4.5 MB, stored through a server route in a public Supabase bucket, the old file is kept so Remove/Replace can be undone); enrich its books (server side, counts summary, retry failed); Delete meetup = 7-day trash with Restore.
   NOT built: Books PDF (Magazine and Classic). `package.json` has no PDF library (no jspdf, pdfkit, pdf-lib, react-pdf; `playwright` is a dev dependency only and cannot run on Vercel), and the rules forbid new dependencies. The PDF sheet says so; an existing PDF link still shows. Decision for you: add `pdf-lib` or `pdfkit` (about 1 day to port both styles), or render PDFs off-Vercel.
7. Record a meetup `/admin/record` (3 steps plus check), draft in localStorage (Resume/Discard on the console), Save meetup = ONE transaction (`POST /api/admin/meetups/record`: the meetup, "presented by", attendance rows, each reader's books through the existing `addBookToMeetup`, make-member choices). New people become guests with the next code for that meetup (`<meetup 3 digits>-<next suffix>`). Notify `/admin/notify`: draft only, copy button, Send is off (no domain). Refresh site data: `POST /api/admin/refresh` runs `revalidatePath('/', 'layout')`; verified on a production build (a venue renamed in the database showed on /meetups only after the refresh).

## Open risks
- Audit rows written before this work (`book.update`) only stored title and author, so their undo restores only those two fields (the label says Edited a book; the check refuses when they changed again).
- Remove member: members removed before this change have no full copy; their restore returns name, bio and books only (as before).
- Unmerge restores the source row and moved ids; if one of the moved rows was deleted since, the undo is refused by the database and nothing changes.
- A recorded meetup's new people get status `guest` and a generated code: a default I took from the existing data (every guest code looks like `091-02`); please confirm.
- The symlink `frontend/node_modules` was committed by mistake and removed again in the next commit; squash when merging.
- Enrich and look-up call two public APIs without keys: rate limits are theirs (a failed source is reported, never faked).
